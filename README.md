# personal-platform-frontend

Frontend таскменеджера на Next.js, React і TypeScript.

## Локальний запуск

1. Встановіть залежності: `npm install`.
2. Скопіюйте `.env.example` у `.env.local`. За замовчуванням `NEXT_PUBLIC_API_URL=http://localhost:4000/api`.
3. Запустіть backend. Його CORS має дозволяти адресу frontend (локально `http://localhost:3000`).
4. Запустіть `npm run dev` та відкрийте `http://localhost:3000`.

Після зміни `NEXT_PUBLIC_API_URL` перезапустіть dev-сервер; для production виконайте нову збірку, оскільки Next.js вбудовує публічні змінні у клієнтський код.

## API

- `GET /tasks` — масив повних Task DTO; `GET /tasks?view=today` — підмножина «Сьогодні»; `GET /tasks?archived=true` — архів.
- `GET /tasks/:id`, `POST /tasks`, `PATCH /tasks/:id` — повний Task із `isToday` та nullable `routineOccurrence`, включно з полями ланцюжка виконань.
- POST вимагає назву, дедлайн і тривалість або початкові підзадачі. PATCH передає лише змінені поля; контекст не входить у body.
- `DELETE /tasks/:id` — видалення задачі.

Список, деталі, POST і PATCH отримують `timezone`, `overdueMode`, `overdueDays` із завантажених налаштувань. Історія, DELETE і маршрути підзадач цих параметрів не отримують. Після запису підзадачі окремий GET батька використовує актуальний контекст; повтор після помилки GET не повторює запис. Повний Task із POST/PATCH оновлює список без додаткового GET, якщо контекст не змінився.

URL: `/` — поточні, `/?view=today` — сьогодні, `/?archived=true` — архів. Архів має пріоритет над view; інші view означають поточні. Переходи зберігають фільтри й сторонні query-параметри; «Скинути» зберігає розділ. Фільтри, пошук, сортування та зміна теми не завантажують задачі повторно.

«Сьогодні» використовує тільки backend isToday. Після фільтрації задачі поділяються на «До виконання» та «Виконано сьогодні» (DONE), зі збереженням сортування всередині кожної групи. Обидві групи входять до загального лічильника. Повний Task DTO містить `completedAt: string | null` — підтверджений backend момент поточного завершення; frontend його не обчислює. Завершення й повторне відкриття переміщують ту саму картку між групами, якщо isToday залишається true; розгортання підзадач зберігається. Поточні задачі й архів залишаються одним списком.

Для визначення timezone майбутніх occurrence кожне завантаження «Сьогодні» паралельно читає поточний список. Один таймер раз на п’ять хвилин перевіряє календарні дати користувача й occurrence з цього списку. GET виконується лише після зміни цих дат, зокрема при поверненні у вкладку; є також кнопка «Оновити список». Вчорашні завершення зникають за новою відповіддю backend. Зміна API-контексту відразу приховує попередній результат; власники відкритих форм тимчасово зберігаються з явним повідомленням про неактуальні картки. Новий контекст після успішного запису оновлюється читанням, без повтору мутації.

Перевірки: `npm run lint`, `npm run typecheck`, `npm run build`.

## Компонування списку задач

Підсумок над фільтрами рахує весь завантажений список поточного розділу: TODO, IN_PROGRESS, неактивні (CANCELED/PAUSED/POSTPONED) та DONE. Він не залежить від пошуку, фільтрів і підзадач та не виконує API-запитів. Розкладка неактивних доступна через клавіатурне розкриття. Під час завантаження або помилки без даних замість достовірних нулів показується повідомлення.

На широкому екрані заввишки від 48rem каркас задач займає viewport, панель керування залишається над областю прокручування, обидві групи «Сьогодні» прокручуються разом. Навігація має власне прокручування, якщо не вміщається. Для вузьких/низьких viewport використовується звичайне прокручування документа, а на мобільному фільтри можна розгорнути кнопкою з кількістю активних умов. Згортання не змінює URL. `/settings` зберігає звичайне компонування.

## Особисті налаштування

Екран `/settings` доступний із меню. Налаштування застосовуються після натискання «Зберегти», без облікового запису. Адаптер `settings-storage.ts` зберігає перевірені поля та `version: 1` у ключі `personal-platform.settings`. Якщо localStorage недоступний, provider зберігає зміни лише в пам’яті поточної вкладки. Події `storage` оновлюють інші вкладки без повторного запису; незбережена форма пропонує завантажити зовнішні значення або зберегти власні.

Часовий пояс за замовчуванням береться з браузера, резервний — UTC. Відображення дат використовує обраний пояс. Відкрита форма фіксує його до закриття, щоб зовнішня зміна налаштувань не переосмислила чернетку. Спільні helpers на `@js-temporal/polyfill` відхиляють неіснуючі години DST та вимагають явного вибору UTC-зсуву для повторених годин. API отримує UTC; незмінені дати не включаються в PATCH (для перенесення зберігається точне початкове `plannedAt`).

Теми використовують спільні CSS-змінні. Системна тема реагує на `prefers-color-scheme`; збережена світла або темна палітра встановлюється блокувальним скриптом у head до відображення сторінки. Він змінює CSSOM, зберігаючи DOM однаковим для SSR і hydration.

Параметри прострочення застосовуються до перегляду «Сьогодні» на backend: limited додає N попередніх календарних днів, none залишає тільки сьогодні, all додає всі попередні дні. Локальні дати й час occurrence відображаються у його календарі, окремо від особистого планування та дедлайну. Беклог і керування Routine у frontend поки відсутні.

Ручна перевірка: збережіть налаштування й перезавантажте сторінку; відкрийте дві вкладки та створіть конфлікт чернетки; перевірте три теми й клавіатурний діалог відкидання змін. Для Europe/Kyiv введіть `2026-03-29 03:30` (неіснуючий час) і `2026-10-25 03:30` (вибір зсуву). Перевіряйте мутації задач тільки на мокованому API.

Незбережені налаштування захищені під час переходів меню та Back/Forward між записами поточного документа. Кореневий `HistoryTraversalProvider` додає власні мітки до state стандартних `pushState`/`replaceState`, зберігаючи решту state і точний URL. При заблокованому `popstate` форма залишається змонтованою, поточний запис відновлюється, а підтвердження відтворює перший запитаний перехід. Нових записів історії для захисту не додається. За наявності публічного Navigation API використовуються точні ключі записів; інакше — індекси History API.

Обмеження: `popstate` надходить після зміни адреси, тому перед відновленням URL може коротко з’явитися адреса призначення. Для F5, закриття вкладки й переходів між різними документами (зокрема до сторінки перед прямим відкриттям `/settings`) працює стандартний `beforeunload`, а не власний діалог. Його показ залежить від правил браузера та взаємодії користувача зі сторінкою. Невідомі записи історії, створені поза відстеженням поточного документа, не відновлюються навмання.

Для перевірки Back/Forward відкрийте задачі → налаштування → архів, поверніться в налаштування та змініть поле. Перевірте обидва напрямки, «Залишитися» (чернетка, адреса й фокус збережені), «Вийти без збереження» (точний запитаний запис), серію швидких натискань і навігацію після збереження. Кількість записів історії після скасування має залишитися незмінною.
